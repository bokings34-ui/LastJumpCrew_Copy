⚓ LastJumpCrew 프로젝트 협업 가이드
이 문서는 프로젝트의 원활한 협업과 파일 충돌 방지를 위한 운영 가이드입니다.

📂 1. 폴더 구조 및 작업 영역
개인 작업: 02~06. [이름]_작업파트 폴더에서만 작업 (타인 폴더 수정 금지)

다른 팀원의 자료 수정이 필요할 경우 팀원에게 알리고 내용 수정을 주석으로 남기기

공용 자산: 02. Final_Prefab 내부 본인 파일들 (최종 합본용, 수정 전 팀 내 공유 필수)

외부 에셋: 99. DownloadAssets 폴더에 저장

🔄 2. 깃허브 협업 루틴 (역할 분담)
① 작업자
작업 시작 전: 최신 상태 동기화 진행(Main 브랜치 최신화와 내 브랜치로 가져오는 방법)

작업 전 : 깃허브데스크탑의 윗 메뉴중 [Branch] 메뉴 클릭 → [Update from main] 클릭
<img width="825" height="747" alt="image" src="https://github.com/user-attachments/assets/794078c0-fde1-4510-a874-832901170331" />

작업 중: 본인 브랜치에서만 작업 (main 브랜치 작업 절대 금지).

작업 완료 시: [Commit] 및 [Push origin] 후, 팀장이나 관련 확인자에게 자신의 브런치에 들어가서 확인 요청

확인이 완료되면 깃허브 웹사이트에서 [Compare & pull request] 클릭 → [Create pull request] 클릭하여 "탁현재"에게 메인병합 요청

② 확인자
검수: 팀원이 작업한 브랜치에 들어가서 재생하여 기능이 이상없는지 검수 및 '스크립트와 파일' 위치 확인.
*   작업공간이 침해되지 않았는지 확인자는 꼭 확인해야합니다

피드백: 수정이 필요하면 가능한 방법중 소통이 되는 방법을 동원해서 작업자에게 확인 요청.

병합: 이상 없으면 "탁현재"에게 요청해서 [Merge pull request] 버튼을 클릭하여 main에 최종 반영.

⚠️ 주의사항
충돌(Conflict) 발생 시: 혼자 해결하려 하지 말고 즉시 팀장에게 호출하세요.

최종 관리: main 병합 권한은 충분한 확인을 거친후 병합하겠습니다.
